# 評価と優先度

## 7つの軸

| ID | 観点 | 確認すること |
| --- | --- | --- |
| `value` | 価値の伝達 | 目的にどう役立つか、最初の成果が分かるか |
| `discovery` | 見つけやすさ | 必要な操作や情報へ、見える導線から到達できるか |
| `comprehension` | 理解しやすさ | 用語・条件・入力・結果を解釈できるか |
| `efficiency` | 操作効率 | 不要な反復や再入力があるか。熟練時にも適するか |
| `recovery` | 失敗からの復帰 | エラーを理解し、修正・取消・中断から再開できるか |
| `trust` | 信頼と判断材料 | 価格、情報の用途、公開範囲、判断に必要な条件が確認できるか |
| `inclusion` | 利用条件への対応 | 選んだ入力方法・画面条件で利用できるか |

`inclusion` は確認した条件だけの評価。キーボード確認のみでアクセシビリティ全体やWCAG適合を保証しない。`trust` も法令・セキュリティの監査ではない。

## 採点

各セッションで各軸を `1`〜`5` または `null` で記録する。以下はこのスキル独自のレビュー尺度で、SUS・NPS・SEQ等の人間が回答する尺度の代用ではない。

| 点 | 基準 |
| --- | --- |
| 1 | この観点の障壁が、対象の目的を妨げる明確な状態を確認 |
| 2 | 大きな分かりにくさや回避操作を伴う |
| 3 | 目的に必要な情報・操作はあるが、小さな摩擦がある |
| 4 | 対象範囲で明確に機能し、問題を確認しなかった |
| 5 | ペルソナの具体的な制約への配慮が証拠付きで確認できる |
| null | 未観察・対象外・資料や環境の制約で判定不能 |

数値には証拠IDと理由を必須とする。「問題が見つからなかった」だけで5にはしない。資料だけでは動的な操作効率や復帰・入力方法の使いやすさは採点しない。静的に見える説明・価値・条件等は資料の範囲に限って採点できる。

標準では総合平均を出さず、ペルソナ別のプロフィールと証拠を示す。重大な問題を平均で隠さない。集計を求められたら、重みと対象を明示し、`null` を0として扱わない。ペルソナ間の点差は母集団の統計差ではない。

## 指摘の単位

指摘は `observed_issue`（観察した問題）、`hypothesis`（影響・行動の仮説）、`strength`（観察した長所）に分ける。

「画面に金額が表示されていない」は限定された表示の事実。「料金が不安で離脱する」は仮説。前者を根拠に後者の確度まで高くしない。資料の抜粋で見えないものを、サービス全体に存在しないと断言しない。

各指摘は、場所、該当ペルソナ・セッション、証拠、事実、解釈、影響、重大度、確認の確かさ、改善案、再検証条件、反証または別の説明を持つ。観察した欠陥をAIの体験談に置き換えない。

### 重大度

- `S3`: 主要な目的を達成できない、または深刻な不利益が具体的に示される。
- `S2`: 大きな摩擦があり、回避策が必要。
- `S1`: 小さな摩擦や限定的な分かりにくさ。
- `S0`: 長所または改善不要の観察。

確認の確かさは、主張を支える証拠に対して `high`（直接確認・再現）、`medium`（限定的な確認）、`low`（未検証の仮説）。仮説は常に `low`。UI事実の確かさと人間行動の再現性は別物。

### 行動の優先度

| 値 | 使う条件 |
| --- | --- |
| `fix_now` | `observed_issue`、`S3`、`high`。現状の重大な障壁を優先修正 |
| `fix_next` | `observed_issue`、`S2`以上、`medium`以上。次の改善候補 |
| `consider` | 小さな観察済みの改善候補 |
| `validate_first` | 仮説または根拠が弱い指摘。影響が重大なら検証自体を優先 |
| `preserve` | 根拠付きの長所。改善時に損なわない |

発生頻度は「今回のセッションのどれで確認したか」まで。人数を分母にした市場の発生率、転換率、支払意思は作らない。改善工数は不明なら不明とし、架空のROIで順位を付けない。

## 統合と再検証

同じ表示でも初心者には説明が必要、熟練者には省略したい等の対立は残す。段階的な説明、設定、役割別導線等を候補にし、誰に何が改善するかを書き分ける。

改善案には検証可能な受入条件を付ける。例：「同じ開始画面からキーボードだけで確定前の確認画面まで到達し、フォーカスが見える」。改善後も同じタスクを再実行し、新旧の証拠を並べる。

人に聞く問いは誘導しない。「このボタンは分かりにくいですよね」ではなく「この状態から予約日時を変更してください」と依頼し、仮説が支持される／反証される行動を先に定義する。
